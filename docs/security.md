# Безопасность

Что защищено, чем именно и что осталось сделать руками.

## Сеть

**Postgres слушает только loopback.** В `docker-compose.yml` порт объявлен как
`127.0.0.1:5433:5432`. Обычная запись `5433:5432` публикует базу в интернет —
и UFW от этого **не спасает**: Docker пишет собственные правила в цепочку
`DOCKER`, а они разбираются раньше правил UFW. Так что «ufw status» может
показывать закрытый порт, пока база отвечает всему миру.

Проверка снаружи (с любой машины, не с сервера):

```bash
nc -zv birkityt.ru 5433     # должно быть "Connection refused" / таймаут
```

Наружу открыты только 22, 80 и 443 — их настраивает
[`scripts/server-setup.sh`](../scripts/server-setup.sh).

## База данных

Пароль роли Postgres обязателен: compose откажется стартовать, если
`POSTGRES_PASSWORD` не задан в `.env`. Раньше там был запасной вариант
`birkityt`, то есть при незаполненном `.env` прод поднимался с паролем,
известным всем, у кого есть исходники.

**Важно при смене пароля.** Postgres задаёт пароль только при первичной
инициализации тома. Если поменять `POSTGRES_PASSWORD` в `.env` у уже работающей
базы, том сохранит старый пароль, а приложение начнёт ходить с новым и получит
отказ. Менять надо в самой базе:

```bash
docker compose exec -T db psql -U birkityt -d birkityt \
  -c "ALTER USER birkityt WITH PASSWORD 'новый-пароль';"
```

и только потом привести `.env` (`POSTGRES_PASSWORD` и пароль внутри
`DATABASE_URL`) в соответствие и перезапустить `docker compose up -d`.

## Админка

| Мера | Где |
|---|---|
| Пароли — bcrypt, cost 12 | [`users/actions.ts`](../src/app/admin/(dash)/users/actions.ts) |
| Проверка сессии в каждом server action | `requireSession()` / `requireAdmin()` |
| Сессия живёт 7 дней вместо 30 | [`src/auth.ts`](../src/auth.ts) |
| Не более 10 попыток входа с IP за 15 минут | [`login/actions.ts`](../src/app/admin/login/actions.ts) |
| Одинаковый текст ошибки для неверного логина и пароля | там же |
| `noindex, nofollow` на всей админке | [`admin/layout.tsx`](../src/app/admin/layout.tsx) |
| `Cache-Control: no-store` на `/admin/*` | [`Caddyfile`](../Caddyfile) |

Права разделены на две роли: `ADMIN` управляет пользователями, `MANAGER` —
только контентом. Проверка стоит в каждом action отдельно, а не только в
layout: server actions — это обычные POST-эндпоинты, и вызвать их можно в
обход интерфейса.

## Публичные формы

Не больше 5 отправок с одного IP за 10 минут, на `/api/contact` и `/api/calc`.
Сверх лимита — ответ 429 с заголовком `Retry-After`. Плюс скрытое поле-ловушка,
которое было и раньше: заполненное ботом, оно возвращает «успех», ничего не
сохраняя.

Ограничитель ([`src/lib/rate-limit.ts`](../src/lib/rate-limit.ts)) держит
счётчики в памяти процесса. Приложение работает в одном контейнере, поэтому
общего хранилища не требуется; счётчики обнуляются при деплое. Это защита от
перебора и спама, а не замена WAF — против распределённой атаки с тысячи
адресов она не поможет.

IP берётся из **последнего** значения в `X-Forwarded-For`: Caddy дописывает
туда реальный адрес подключения, и подделать его клиент не может, тогда как
первое значение в списке приходит от клиента.

## Заголовки

Настроены в [`Caddyfile`](../Caddyfile): HSTS на два года,
`X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`,
`Content-Security-Policy: frame-ancestors 'self'`, `Referrer-Policy`,
`Permissions-Policy`, скрытый баннер сервера.

Проверить после деплоя: <https://securityheaders.com/?q=birkityt.ru>

Осторожно с HSTS: `includeSubDomains` браузеры кешируют на весь срок. Если
когда-нибудь понадобится поддомен по обычному HTTP, эту директиву нужно убрать
**заранее**.

Полноценный CSP (ограничение источников скриптов) намеренно не включён:
вебвизор Яндекс.Метрики внедряет скрипты и открывает WebSocket, и строгая
политика его ломает. Если решите включать — начинайте с
`Content-Security-Policy-Report-Only` и смотрите отчёты неделю.

## Загруженные файлы

Все картинки перекодируются в WebP через `sharp`
([`src/lib/uploads.ts`](../src/lib/uploads.ts)), то есть исходный файл на диск
не попадает вообще. SVG убран из списка отдаваемых типов: он может содержать
скрипты и выполнялся бы с домена сайта. Каталог `/uploads` отдаётся с
`nosniff` и `default-src 'none'; sandbox`.

## Что стоит сделать дополнительно

1. **Копии бэкапов вне сервера** — см. [backups.md](backups.md).
2. **Вход по SSH-ключу, без пароля**: в `/etc/ssh/sshd_config` поставить
   `PasswordAuthentication no` и `PermitRootLogin no`.
3. **Автообновления безопасности**: `apt-get install -y unattended-upgrades`.
4. **fail2ban** для SSH.
5. **Двухфакторная авторизация в админке** — сейчас её нет. Если панелью
   пользуется несколько человек, это следующий по важности шаг после пунктов
   1–2.
