# Яндекс.Метрика

Счётчик: **111863215**. Идентификатор задаётся переменной
`NEXT_PUBLIC_YANDEX_METRIKA_ID`. Если она пустая — счётчик и cookie-баннер не
рендерятся вообще, ошибок в консоли нет.

## Как это устроено

| Файл | Роль |
|---|---|
| [`src/lib/metrika.ts`](../src/lib/metrika.ts) | ID счётчика, хранение согласия, `reachGoal()` |
| [`src/components/site/Analytics.tsx`](../src/components/site/Analytics.tsx) | решение о cookie, загрузка счётчика, хиты при смене маршрута |
| [`src/components/site/CookieBanner.tsx`](../src/components/site/CookieBanner.tsx) | плашка согласия |
| [`src/components/site/GoalLink.tsx`](../src/components/site/GoalLink.tsx) | ссылки с целью для серверных компонентов |

Подключено в `(site)`-layout, то есть на всех публичных страницах. В админку
счётчик намеренно не попадает — иначе вебвизор писал бы сессии с данными
клиентов из заявок.

Параметры инициализации: `clickmap`, `trackLinks`, `accurateTrackBounce`,
`webvisor`, `trackHash` — все `true`.

## Согласие на cookie

Счётчик **не загружается**, пока посетитель не нажал «Принять» в плашке.
Решение хранится в `localStorage` под ключом `birkityt.cookie-consent`
(`granted` / `denied`). При отказе никаких запросов к `mc.yandex.ru` не идёт.

Из-за этого статистика будет ниже реального трафика — часть визитов не попадёт
в Метрику. Это следствие требования собирать данные только после подтверждения.

Единственное исключение — `<noscript>`-пиксель: он отдаётся в HTML всегда,
потому что посетителю с отключённым JavaScript плашку показать невозможно.
Если такое поведение не нужно — уберите блок `<noscript>` из `Analytics.tsx`.

## Хиты при переходах

App Router меняет страницы через History API без перезагрузки, поэтому счётчик
сам их не видит. `Analytics.tsx` отправляет `ym(id, 'hit', ...)` на каждую смену
`pathname`. Первый просмотр отправляет сам `init` — он не дублируется.

## Цели

Все цели — типа **JavaScript-событие**. Идентификатор в интерфейсе Метрики
должен точно совпадать с колонкой «Идентификатор».

| Идентификатор | Когда срабатывает | Где в коде |
|---|---|---|
| `form_submit` | Успешная отправка заявки — только после ответа сервера | `ContactSection.tsx`, `Calculator.tsx` |
| `click_phone` | Клик по номеру телефона | шапка, футер, секция контактов |
| `click_whatsapp` | Клик по ссылке WhatsApp | футер |
| `click_telegram` | Клик по ссылке Telegram | шапка, футер |
| `click_max` | Клик по ссылке MAX | шапка, футер |
| `click_email` | Клик по e-mail | футер, секция контактов |
| `calc_open` | Переход в калькулятор | шапка (десктоп + мобильное меню), CTA на главной, CTA внизу `/price` |

`form_submit` вызывается только при `result === "success"`, не по клику по
кнопке — отказы и ошибки валидации в цель не попадают.

Ссылка на VK в футере целью не размечена: её нет в согласованном списке.
Если нужна — заводим `click_vk` в `Goal` в `src/lib/metrika.ts` и здесь.

## Настройка в интерфейсе Метрики

1. Метрика → Настройка → вкладка **Цели** → «Добавить цель».
2. Тип условия — **JavaScript-событие**.
3. В поле «Идентификатор цели» — значение из таблицы выше, без изменений.
4. Повторить для каждой строки.

## Смена ID счётчика

`NEXT_PUBLIC_*` вшивается в клиентский бандл на этапе `next build`, а не
читается в рантайме. В Docker переменная передаётся build-аргументом, поэтому
после изменения нужна пересборка образа:

```bash
docker compose build web && docker compose up -d web
```

Просто поменять значение в `.env` и перезапустить контейнер — недостаточно.
