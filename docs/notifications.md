# Уведомления о заявках

Когда посетитель отправляет контактную форму или расчёт из калькулятора,
заявка сохраняется в базу и параллельно уходит в два канала: Telegram и почту.
Каналы независимы — если один не настроен или недоступен, второй всё равно
сработает, а заявка в любом случае останется в разделе «Заявки».

| | |
|---|---|
| Отправка | [`src/lib/notify.ts`](../src/lib/notify.ts) |
| Telegram | [`src/lib/telegram.ts`](../src/lib/telegram.ts) |
| Почта | [`src/lib/mailer.ts`](../src/lib/mailer.ts) |
| Проверка | `/admin` → блок «Уведомления о заявках» |

## Настройка бота

**1. Создать бота.** В Telegram найдите [@BotFather](https://t.me/BotFather),
отправьте `/newbot` и ответьте на два вопроса — имя и username (username должен
заканчиваться на `bot`). В ответ придёт токен вида
`8123456789:AAH...` — это `TELEGRAM_BOT_TOKEN`.

**2. Куда слать.** Решите, приходят заявки в личку одному человеку или в общую
группу.

*В личку:* напишите своему боту любое сообщение (он не ответит — так и надо).
Затем откройте в браузере:

```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

Найдите в ответе `"chat":{"id":123456789` — это `TELEGRAM_CHAT_ID`.

*В группу:* создайте группу, добавьте туда бота, отправьте в неё любое
сообщение и откройте тот же `getUpdates`. Идентификатор группы отрицательный,
например `-1001234567890` — минус обязательно копировать.

Бот не может написать первым: пока ему не отправили сообщение (или не добавили
в группу), `getUpdates` вернёт пустой список.

**3. Прописать в `.env` на сервере:**

```bash
TELEGRAM_BOT_TOKEN="8123456789:AAH..."
TELEGRAM_CHAT_ID="123456789"
```

**4. Перезапустить.** Эти переменные читаются в рантайме, пересборка образа не
нужна:

```bash
docker compose up -d web
```

В выводе должно быть `Recreated`. Если `Running` — переменные не изменились,
проверьте `docker compose config | grep TELEGRAM`.

## Проверка

Зайдите в админку, на главный экран `/admin`. Там блок «Уведомления о заявках»:
две метки показывают, настроены ли каналы, а кнопка отправляет тестовое
сообщение в чат.

Кнопка показывает не «отправлено», а реальный результат: если Telegram отверг
запрос, выводится его текст ошибки. Частые случаи:

| Ошибка | Причина |
|---|---|
| `Unauthorized` | неверный токен |
| `chat not found` | неверный `TELEGRAM_CHAT_ID`, либо боту ещё не писали |
| `bot was blocked by the user` | бот заблокирован в личке |
| `Сеть или таймаут` | сервер не достучался до api.telegram.org |

## Что приходит

```
🟦 Заявка с сайта

Имя: Иван Петров
Телефон: +7 999 000-11-22
Почта: ivan@example.com
Сообщение: нужно 500 шт тканевых бирок
```

Заявка из калькулятора приходит с 🧮 и дополнительно содержит материал,
вариант, тираж, надбавки и рассчитанную сумму.

## Ограничения

Отправка происходит **внутри** запроса, пока посетитель ждёт ответ формы. У
Telegram стоит таймаут 8 секунд, у SMTP — 8 на соединение и 10 на обмен.
Если оба канала подвиснут, посетитель прождёт около десяти секунд, но заявку
всё равно сохранит: запись в базу происходит раньше отправки уведомлений.

Повторных попыток нет. Если Telegram лежал в момент заявки, сообщение
потеряется — но сама заявка останется в админке. Поэтому раздел «Заявки»
остаётся основным местом, а уведомления — способом узнать быстрее.
