# Уведомления о заявках

Когда посетитель отправляет контактную форму или расчёт из калькулятора,
заявка сохраняется в базу и параллельно уходит в два канала: бот **MAX** и
почта. Каналы независимы — если один не настроен или недоступен, второй всё
равно сработает, а заявка в любом случае останется в разделе «Заявки».

| | |
|---|---|
| Отправка | [`src/lib/notify.ts`](../src/lib/notify.ts) |
| Бот MAX | [`src/lib/max.ts`](../src/lib/max.ts) |
| Почта | [`src/lib/mailer.ts`](../src/lib/mailer.ts) |
| Поиск chat_id | [`scripts/max-chat-id.sh`](../scripts/max-chat-id.sh) |
| Проверка | `/admin` → блок «Уведомления о заявках» |

Документация API: <https://dev.max.ru/docs-api>

## Как создать бота

Есть два пути. Первый быстрее, второй нужен, если требуется официальный
верифицированный бот.

### Через @MasterBot (быстрый путь)

1. Откройте MAX, найдите в поиске **@MasterBot** и начните с ним диалог.
2. Отправьте команду создания бота и следуйте подсказкам.
3. Придумайте **username** — он должен быть длиннее 11 символов и
   заканчиваться на `bot` или `_bot`, например `birkityt_orders_bot`.
   Username уникален на всю платформу.
4. Укажите **отображаемое имя** — то, что видно в шапке диалога. Уникальность
   не требуется, подойдёт «БИРКИТУТ — заявки».
5. MasterBot пришлёт **токен**. Это и есть `MAX_BOT_TOKEN`.

### Через платформу для разработчиков

На <https://dev.max.ru> нужен подтверждённый профиль организации, ИП или
самозанятого — у вас есть ИП, так что путь доступен. После проверки бота токен
лежит в разделе **Чат-боты → Интеграция → Получить токен**.

> Токен — это полный доступ к боту. Не храните его в репозитории и не
> передавайте посторонним.

## Как узнать chat_id

В отличие от Telegram, здесь нельзя просто открыть ссылку в браузере: MAX
требует токен в HTTP-заголовке, а `chat_id` отдаётся только внутри событий
(`GET /updates` или webhook).

**Сначала напишите боту** — иначе событий не будет и список окажется пустым:

* для личных уведомлений — отправьте боту любое сообщение в MAX;
* для общего чата — создайте группу, добавьте бота и напишите туда.

Затем на сервере:

```bash
bash scripts/max-chat-id.sh
```

Скрипт проверит токен через `GET /me`, запросит события и выведет все
найденные идентификаторы в готовом виде:

```
MAX_CHAT_ID="-1001234567890"   Заявки БИРКИТУТ
```

Токен берётся из `.env`; можно передать его первым аргументом, если `.env` ещё
не заполнен.

## Настройка

В `.env` на сервере:

```bash
MAX_BOT_TOKEN="токен-от-MasterBot"
MAX_CHAT_ID="-1001234567890"
```

Перезапуск:

```bash
docker compose up -d web
```

В выводе должно быть `Recreated`. Пересобирать образ **не нужно** — это
обычные переменные окружения, читаются в рантайме.

## Проверка

Админка → главный экран `/admin` → блок «Уведомления о заявках». Две метки
показывают, настроены ли каналы, кнопка отправляет тестовое сообщение.

Кнопка сначала дёргает `GET /me` и только потом отправляет сообщение — это
позволяет различить «неверный токен» и «неверный чат», которые иначе
выглядели бы одинаково. В случае успеха показывается, от имени какого бота
ушло сообщение.

| Что показано | Причина |
|---|---|
| `Токен не принят: MAX ответил 401` | неверный или отозванный токен |
| `MAX ответил 404` | неверный `MAX_CHAT_ID` |
| `MAX ответил 403` | бота удалили из чата или он там не состоит |
| `Сеть или таймаут` | сервер не достучался до `platform-api2.max.ru` |

## Что приходит

```
🟦 Заявка с сайта

Имя: Иван Петров
Телефон: +7 999 000-11-22
Почта: ivan@example.com
Сообщение: нужно 500 шт тканевых бирок
```

Заявка из калькулятора приходит с 🧮 и дополнительно содержит материал,
вариант, тираж, надбавки и рассчитанную сумму.

Значения выделены жирным через `format: "html"`, поэтому текст от посетителя
экранируется: иначе сообщение «цена < 10» ломало бы разбор разметки, и
уведомление потерялось бы целиком.

## Технические детали

Две вещи в API MAX отличаются от привычного и легко ломаются при правке:

1. Токен передаётся в заголовке `Authorization` **без префикса `Bearer`**.
   Авторизация через query-параметр больше не поддерживается.
2. Получатель (`chat_id`) — это **query-параметр**, а текст лежит в теле
   запроса. Не наоборот.

Фактический запрос:

```
POST https://platform-api2.max.ru/messages?chat_id=...&disable_link_preview=true
Authorization: <токен>
Content-Type: application/json

{"text":"…","format":"html","notify":true}
```

Ограничения платформы: 4000 символов на сообщение (длинные обрезаются),
2 сообщения в секунду на чат, 30 запросов в секунду на весь API.

## Ограничения нашей реализации

Отправка происходит **внутри** запроса, пока посетитель ждёт ответ формы.
Таймаут MAX — 8 секунд, SMTP — 8 на соединение и 10 на обмен. Если оба канала
подвиснут, посетитель прождёт около десяти секунд, но заявку всё равно
сохранит: запись в базу происходит раньше отправки уведомлений.

Повторных попыток нет. Если MAX недоступен в момент заявки, сообщение
потеряется — но сама заявка останется в админке. Поэтому раздел «Заявки»
остаётся основным местом, а уведомления — способом узнать быстрее.

Тот же бот шлёт отчёты об ошибках ночного бэкапа — [`scripts/backup.sh`](../scripts/backup.sh)
читает те же две переменные.
